1. The big picture

UtsabPay can pay through more than one company (a vendor). Today: ViMoPay for payouts, and Bill Avenue or SuivrePay for credit card bill payment. Payment Vendor Routing is the admin page where you decide, without any code change:

  • which vendor serves a product,
  • in what order (Vendor 1 first, then Vendor 2...),
  • with what limits (minimum/maximum amount, daily, monthly and yearly count and amount),
  • and which merchants and franchises get that routing.

The five building blocks

BlockWhat it isWhere you set it
ProductA thing we sell. Here: Payout (code 001) and Bill Payment (code 002, with the category "Credit Card").Payment > Payment Products
VendorThe outside company that really moves the money (ViMoPay, Bill Avenue, SuivrePay).Payment > Payment Vendors and Payment Vendors Credentials
Product Vendor link"This vendor is allowed to serve this product (and these categories)."Routing > Product Vendors tab
RoutingA named recipe: vendors in order + limits + retry rule. Example: Payout - Default.Routing > Routings tab
Assignment"This merchant/franchise uses this routing." One account has one routing per product.Routings tab > Accounts / Manage button
Vendor exists + credentials→ Link vendor to product→ Create routing (order + limits)→ Assign merchants / franchises→ Switch on: Payout Engine + Menu Rules

Three switches decide whether routing is really used

Saving a routing alone changes nothing for anyone. Routing starts to act only when these are switched on:

SwitchWhereWhat it controls
Payout flow (Old / Pilot / New flow for everyone)Payout Engine tabWhich payout engine runs. The new flow is the safe one: it takes the money first, calls the vendor with no wallet lock, then records the answer, and every try is saved as an attempt.
Use routing for payouts (tick box)Payout Engine tabThe new flow chooses the vendor from the merchant's routing and checks its limits before any money is taken. Off = always the fixed vendor.
Menu Rules (Off / Only these accounts / Everyone)Menu Rules tabA merchant sees the Payout menu only if a Payout routing is assigned. Credit card menus follow the routing's Vendor 1.
Good to know All three switches are stored on the server and refresh by themselves within about 15 seconds. No restart is needed. Merchants see menu changes after they reload the page.

2. What must exist before routing

Routing only chooses between things that already exist. Check these first (admin menu names in brackets):

#ItemWhy
1Payment Vendors - ViMoPay, Bill Avenue, SuivrePay are created and Active.An inactive vendor cannot be linked or chosen.
2Payment Vendors Credentials - keys for each vendor are saved.Without credentials the vendor call fails.
3Payment Products - Payout and Bill Payment exist.Routings belong to a product.
4Payment Charges - the charge for the product (for credit card: BBPS_CREDIT_CARD) is set up.The wallet debit = amount + charge. No charge, no correct debit.
5Merchant Settings (Others > Merchant Settings) - switch Payout and Credit Card Bill Payment ON per merchant/franchise.These per-account switches still apply on top of routing. A menu shows only if its switch is ON and the routing allows it.
6Your admin role has the permission Payment Vendor Routing.The page is admin only.

3. Going live with no old flow: step by step

Goal: every payout uses the new flow and follows routing, and a merchant or franchise sees the Payout / credit card menus only when routing is assigned. Follow the order. Do not skip step 4: accounts without a routing will lose the menu in step 8.

Before you start Do this in a quiet hour, with one test merchant ready. Have the screens open in two tabs: the admin page and the test merchant login.
  1. Check vendors. Payment Vendors: all needed vendors Active. Credentials saved.
  2. Link vendors to products (Product Vendors tab, section 4b). Payout → ViMoPay. Bill Payment → Bill Avenue (category Credit Card) and SuivrePay (category Credit Card).
  3. Create or open the routings (Routings tab, section 4a):
    • Payout - Default: Vendor 1 = ViMoPay. Set realistic limits (see the limit advice below).
    • Bill Payment - Default: Vendor 1 = the vendor whose screen you want merchants to use for credit card (Bill Avenue or SuivrePay), Vendor 2 = the other one.
  4. Assign every account that must keep the menu. In each routing press Manage, choose Merchants (then Franchises), press Select all, then Assign. The box says "Accounts with no routing for Payout (N)". When N is 0 for the accounts you want, you are done. Repeat for each product.
  5. Check a sample in Check a Merchant (section 4c): one merchant and one franchise, for Payout and for Bill Payment / Credit Card. The answer must name the vendor you expect.
  6. Merchant Settings: the Payout and Credit Card Bill Payment switches are ON for the accounts that should use them.
  7. Payout Engine tab (section 4d): choose New flow for everyone, tick Use routing for payouts, press Save, confirm. Wait about 15 seconds.
  8. Menu Rules tab (section 4e): choose Everyone, press Save, confirm. Wait about 15 seconds.
  9. Test with a real small payment from the test merchant (₹100 payout; a small credit card bill), then look at the Attempts list and History tab.
  10. Watch the first day. Open Attempts now and then. Any problem: go to section 8 (switching back).

Advice for the limits (step 3)

LimitAdvice
Min / Max amountViMoPay accepts at least ₹100 and below ₹1,00,000. The system already refuses payouts outside ₹100 - ₹99,999 before any debit. Set the same here (min 100, max 99999) so the screen shows it.
Daily transactions / amountLeave empty for no limit, or set the number your vendor agreement allows. All merchants together share this one limit.
Monthly / YearlySame idea. A longer period can never be smaller than a shorter one (monthly ≥ daily, yearly ≥ monthly).
Important about limits A limit empty = no limit. A limit is for all merchants together, not per merchant. Payments that are still Pending count toward the limit. Separately, the vendor ViMoPay has its own rule that one beneficiary can receive only a small amount per day. That is the vendor's rule and cannot be set here.
What "no old flow" means in practice The old payout flow is not deleted. It is only not used while the mode is New flow for everyone. This is deliberate: if something unexpected happens you can switch back in one click (section 8).

4. The six tabs, one by one

Open: Admin sidebar > Payment > Payment Vendor Routing. The page has six tabs.

4a. Routings tab

Purpose: make and manage the routings (the "recipes"), and decide who uses them.

ColumnMeaning
RoutingThe name you gave it.
ProductPayout or Bill Payment.
Vendors, in orderBlue chips: 1. Vendor, 2. Vendor. A grey crossed-out chip is switched off. Hover a chip to see its limits.

The Product filter at the top shows one product only. Add Routing creates a new one.

Add / Edit Routing form

FieldWhat to enter / what happens
Product *Payout or Bill Payment. Cannot be changed after saving. The vendor lists below show only vendors linked to this product (Product Vendors tab).
Routing name *Free text, e.g. Payout - Default. Use clear names, they appear everywhere.
StatusOn / Off. Off = the routing exists but nobody can use it.

Add vendorAdds Vendor 2, 3... (up to 10, each vendor once). The up/down arrows change the order; the bin removes a row.

Min / Max amount per transactionThis vendor is used only for amounts inside this range. Outside = skipped.
Daily transactions / amountHow many payments / how much money this vendor may take today, all merchants together.
Monthly transactions / amountSame for the calendar month.
Yearly transactions / amountSame for the calendar year (or financial year if the server is set to start in April).
Retries on the same vendorHow many times a clearly-not-processed try is repeated.
Wait between attempts (seconds)Pause between tries (never more than 10 seconds in practice).
How the vendor is chosen for a payout The system walks down the list. For Vendor 1: is it ON? is the amount inside min/max? is today's count/amount, this month's and this year's still below the limit? If everything is fine, Vendor 1 is used. If not, Vendor 2 is looked at, and so on. If no vendor can serve it, the payout is refused before any money moves and the merchant sees the exact reason (section 6).
Retries and switching Retries and "go to the next vendor" happen only when a vendor clearly did not process the payment. If the answer is unclear (Pending/Unknown), the payment is never repeated, so money is never paid twice. With one payout vendor (ViMoPay only) retries do nothing yet; they become active when a second payout vendor is added.

Managing accounts (Manage button)

  1. Choose Merchants or Franchises.
  2. The list shows only accounts with no routing yet for this product. Search and pick, or press Select all N.
  3. Press Assign. They move to the "Assigned" list.
  4. To remove: tick the accounts in "Assigned", press Remove, confirm. They then have no routing for that product (and, with Menu Rules on, lose the menu).
One account has only one routing per product. To move an account from one routing to another, remove it from the first, then assign it to the second.

Switching off or deleting a routing

If accounts are assigned, the screen asks first. Off or deleted means those accounts have no vendor for that product. Do this only after moving the accounts elsewhere.

4b. Product Vendors tab

Purpose: say which vendors are allowed to serve which product. The routing form lists only these vendors.

  1. Choose the Product.
  2. In "Link a vendor to this product" choose the Vendor.
  3. Categories (only for Bill Payment): pick one or more from the dropdown (for example Credit Card). Nothing chosen = all categories. The list is built from the real biller data, so nobody types a wrong name.
  4. Keep Switched on ticked and press Save.

Saving a vendor that is already linked updates it. A vendor that is used inside a routing cannot be switched off or removed until it is taken out of that routing.

For Payout the category box says "This product has no categories".

4c. Check a Merchant tab

Purpose: answer "which vendor would this merchant/franchise get?" Nothing is reserved or changed. Use it before every go-live step and when a merchant complains.

  1. Choose Product.
  2. Choose Merchant or Franchise and search the account.
  3. Optional Amount: to test the min/max rules.
  4. Optional Category (shown only for products with categories): e.g. Credit Card.
  5. Press Check.

The result shows the account, its routing, a green/amber sentence, and a table: for every vendor in order, whether it is chosen and, if not, the reason (switched off, below minimum, above maximum, does not serve this category...).

What this check does not include How much of the daily/monthly/yearly limit is already used today. The real payment checks that; this screen only explains the saved settings.

4d. Payout Engine tab

Purpose: choose the payout engine, and whether payouts follow routing. Below it is the list of Attempts.

OptionWhat happens
Old flow (today)Every payout works as before routing existed. Routing is ignored.
PilotOnly the chosen accounts use the new flow. Everyone else keeps the old flow. Used for testing with one or two accounts.
New flow for everyoneEvery payout uses the new flow. This is the go-live setting.
Use routing for payouts (tick)The new flow picks the vendor and checks limits from the account's routing. Accounts without routing keep using the fixed vendor. Off = routing ignored for payouts.

Press Save and confirm the pop-up. It takes effect within about 15 seconds. Payouts already running finish normally.

What is the "old flow" and why switch?

Old flowNew flow
How it worksEverything in one big step: check, take the money, call the vendor and wait, save the result.Three separate steps: (1) check and take the money, commit; (2) call the vendor; (3) record the answer.
Wallet locked while the vendor answersYesNo
Follows routing (vendor, limits, retries)No, one fixed vendorYes, when "Use routing for payouts" is ticked
Every vendor try recorded (Attempts)NoYes
Refused before money movesBasic checks onlyBasic checks and routing limits

The old flow is kept in the system only as a safety net. For go-live choose New flow for everyone and tick Use routing for payouts. The choice is stored on the server and survives restarts and deployments, so you do it once.

Is there a "credit card engine"? No. Credit card bill payment has only one flow, so it needs no engine switch. Credit card follows the Menu Rules tab only (section 4e).

What the new payout flow does, step by step

  1. Checks: amount between ₹100 and ₹99,999, enough wallet balance, payout switch on. If the routing is used: a vendor is chosen and its limits are checked. A refusal here means no money moved.
  2. Takes the money (amount + charges) from the wallet and saves the payout as Pending, in one safe step.
  3. Calls the vendor (no wallet lock while waiting).
  4. Records the answer: Success → done. Failed → the money is refunded exactly once. Pending → waits for the vendor's callback; when it arrives the payout and its attempt are closed.

Attempts list

ColumnMeaning
ReferenceThe payout reference sent to the vendor.
VendorWhich vendor was called.
Attempt#1 SUCCESS, #1 FAILED, #1 PENDING... number and result of the try.
PayoutFinal status of the payout itself.

4e. Menu Rules tab

Purpose: a merchant or franchise sees a menu only if a routing is assigned to it.

ModeWhat happens
OffEvery account sees every menu (as before).
Only these accountsThe rules apply only to the accounts you pick. Use it to test with one merchant.
EveryoneThe rules apply to every merchant and franchise. Go-live setting.

What a merchant sees when the rules apply

SituationResult
Has a Payout routing (On)Payout menu is shown. (Still needs the Payout switch in Merchant Settings.)
No Payout routingPayout menu is hidden.
Has a Bill Payment routing and Vendor 1 for "Credit Card" is Bill AvenueBill Pay screen is shown; the Credit Card (SuivrePay) menu is hidden.
Vendor 1 for "Credit Card" is SuivrePayThe Credit Card menu is shown; only the Bill Pay screen is hidden (Transaction Status and complaints stay).
No Bill Payment routingBoth Bill Pay and Credit Card menus are hidden.
FranchiseHas no Bill Pay screen. Keeps Credit Card unless its routing offers only Bill Avenue.
Built to fail safe Admins are never affected. If anything goes wrong while reading the rules, nothing is hidden. A vendor is recognised by its name, which must contain "Bill Avenue" or "SuivrePay" - keep those names when you edit vendors.
Two details (1) For credit card, the server also refuses the other vendor's screen if someone opens its address directly, and nothing is debited. (2) The Payout rule hides the menu only; it does not by itself refuse payouts (payout limits are checked by routing, section 4d). Merchants see a menu change after they reload the page.

4f. History tab

Purpose: the audit trail. Every change made in this page is recorded: who, when, what, and the details.

Examples of rows: routing created or changed, accounts assigned/removed, vendor linked, Payout Engine mode changed, Menu Rules changed. Use it to answer "who changed this and when?".

Set Menu Rules to EveryoneAccounts with no routing lose the Payout / credit card menus. Assign them first.

Remove a merchant from a Payout routingPayout menu disappears after reload.

Put SuivrePay firstMerchants see the Credit Card menu; the Bill Pay screen hides.

MessageMeaning / what to do

7. Daily work

A new merchant or franchise joins

  1. Create the account as usual.
  2. Merchant Settings: switch Payout and/or Credit Card Bill Payment ON.
  3. Assign the routing (Routings > Manage > Assign). Without it, with Menu Rules on, the menus stay hidden.
  4. Check a Merchant to confirm the vendor.
Remember New accounts are not assigned automatically. "Menu missing for a new merchant" almost always means no routing is assigned yet.

Change the vendor order or limits

Routings > Edit > change order with the arrows or edit limits > Save. Effective for the next payment. Check History.

Check how a day went

  • Payout Engine > Attempts: look for FAILED and PENDING rows and read the vendor answer.
  • History: who changed what.
  • Reports: Credit Card Bill Report and payout reports for money totals.

8. Switching back safely

ProblemQuick actionTakes effect
Payouts behave strangely after go-livePayout Engine → Old flow → Save~15 seconds
Payout is refused wrongly by routingUntick Use routing for payouts → Save (the new flow stays, vendor becomes fixed)~15 seconds
Menus are missing for many peopleMenu Rules → Off → Save~15 seconds, reload page
One routing is wrongEdit it, or move accounts to another routingNext payment

Money already taken for a payout the vendor refused is refunded automatically, once.
